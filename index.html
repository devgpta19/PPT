Act III: Core AI Architecture

What is RAG & Why Did We Use It?

RAG (Retrieval-Augmented Generation) transforms a guessing AI into a verified open-book factory expert.

1. RETRIEVE Qdrant Cloud

Employee asks any question → System searches 768-dim vector chunks and retrieves the exact 1–2 paragraphs from factory manuals.

2. AUGMENT Strict Context

System packages the question + retrieved paragraphs into a strict prompt: “Answer ONLY using these verified facts.”

3. GENERATE Local Phi-4 Mini

AI reads those exact paragraphs and generates a verified 1-2-3 checklist with 0% hallucination.

❌ Plain ChatGPT: Closed-Book Exam

  • Answers strictly from memorized public internet training data.
  • Has never seen Atharva Sugar rules → hallucinates fake buttons.
  • Requires expensive re-training and GPU fine-tuning to update knowledge.

✅ Our RAG System: Open-Book Exam

  • Zero Guessing / 100% Safety: Answers are strictly bounded by official company manuals.
  • Instant Updates (2 Seconds): Upload a new PDF manual → indexed instantly without AI re-training.
  • $0 Cloud Cost & LAN Privacy: Local small language models (Phi-4 Mini) keep all mill data private.
CRITICAL TALKING POINT: Explain RAG simply using the 'Open-Book Exam' analogy: Standard AI takes a closed-book exam and guesses custom factory rules, inventing fake buttons. RAG forces an open-book exam in 3 steps: 1) RETRIEVE: Search Qdrant for the exact page in factory manuals. 2) AUGMENT: Hand the question + those verified paragraphs to the AI. 3) GENERATE: Draft a verified 1-2-3 checklist using ONLY those facts. Why we used RAG: 1) Zero Hallucinations for mill safety, 2) Instant knowledge updates by uploading a PDF in 2 seconds with zero retraining costs, 3) 100% data privacy on factory LAN.
Act III: The Why

Why Two Databases? (SQL Server + Qdrant)

Why traditional relational databases cannot perform semantic search on their own.

The Library Analogy:
• SQL Server is the Register Book: Tracks employee logins, passwords, permissions, and audit logs. It is strict and exact.
• Qdrant is the Expert Librarian: Has read every manual. When you ask "How do I onboard a farmer?", it knows you mean "Cane Registration" and pulls the right page in 10ms.

🗄️ SQL Server (The Filing Cabinet)

  • Finds exact keyword matches only.
  • "Onboard Farmer" $\neq$ "Cane Registration" (SQL fails!).
  • Guarantees ACID security for user accounts & chats.

🧠 Qdrant (The Smart Search Brain)

  • Searches by human meaning, synonyms, and intent.
  • Knows "Farmer Onboarding" means "Cane Registration".
  • Restricts searches strictly to the active ERP department.
The Library analogy makes this instantly clear: SQL is the ledger for security; Qdrant is the brain for meaning.

Act IV: Universal Integration & Security

Universal SSO: Symmetric Security & Extensible RBAC

How single-API-key decoupling, sub-millisecond symmetric signing, and extensible roles make the assistant universal.

🔌
1. Decoupled & Portable

Runs as an independent microservice. Connects to ANY host application (Sugar ERP, Weighbridge scale kiosks, Farmer mobile app) via a single API key.

🔑
2. Symmetric (HMAC-SHA256)

Uses a shared enterprise secret key (Jwt:Key). Sub-millisecond (<0.05ms) in-memory verification and 100% offline factory LAN compatibility without cloud IdP lag.

👥
3. ERP-Ready Extensible RBAC

2 core active roles (Admin & User). Stored as an open nvarchar(50) claim in SQL Server → ready to add Supervisor, WeighbridgeClerk, Accountant instantly.

🔄
4. Silent Refresh & IDB

Multi-tab session sharing in browser IndexedDB. Axios interceptor silently renews 120-min tokens in the background so night-shift operators are never logged out.

⚡ Cryptographic Signature Code: Implemented via ASP.NET Core SymmetricSecurityKey in JwtService.cs and validated in Program.cs.
SecurityAlgorithms.HmacSha256 (HS256)
CRITICAL TALKING POINT: Emphasize that our SSO implementation is: 1) 100% INDEPENDENT: Any mill app connects with a Single API Key. 2) SYMMETRIC CRYPTOGRAPHY: Uses HMAC-SHA256 with a shared secret key. This gives sub-millisecond (<0.05ms) verification with zero network round-trip delay, and works 100% offline on the factory LAN without external cloud OAuth dependencies. 3) ERP-READY RBAC: 2 active roles (Admin & User) ensure clear governance, but the database uses an open string claim, ready to support custom roles (Supervisor, Accountant, Chemist) anytime.

Executive & Evaluator Q&A Defense

Hardened answers to key technical, security, and architectural questions.

Q: What if someone asks unrelated things (e.g. cricket)?

Answer: The Out-of-Scope Gate calculates vector similarity. When similarity is low, the AI is never called; it safely replies: “Data for this topic has not been uploaded yet.”

Q: Does factory data leak to OpenAI or Google?

Answer: No. By default, the system runs 100% locally on factory machines via Microsoft Phi-4 Mini. Confidential payroll and cane data never leave the private factory LAN.

Q: Can we update procedures when rules change?

Answer: Yes! Administrators simply upload the new PDF/Word manual in the Admin Hub. It auto-chunks and indexes into Qdrant in 2 seconds with zero retraining.

Q: How do you guarantee the AI doesn't modify numbered steps?

Answer: Our Direct-SOP Verbatim Pass copies the exact text directly from the verified manual without letting the AI rephrase it, guaranteeing 100% compliance.

Q: Did we use Symmetric or Asymmetric security for SSO?

Answer: Symmetric (HMAC-SHA256) using a shared secret key. It delivers sub-millisecond (<0.05ms) in-memory verification and operates 100% offline on the factory LAN with zero cloud IdP overhead.

Q: Does the system support only 2 roles?

Answer: 2 roles (Admin and User) are actively enforced for clean governance, but the database uses an open nvarchar(50) claim, making it ERP-ready to add custom roles (Supervisor, Accountant, Chemist) anytime.

Review these 6 answers. They handle all common tough questions from judges and management, including our cryptographic choice (Symmetric HMAC-SHA256) and extensible role design.
